# 算力端任务显示

本机任务以端到端任务为单位。普通聊天和串行 Agent 各生成一条任务；拆分模式在主任务下为每个子任务保留一条完整记录。工具调用和内部模型调用只出现在详情中。

## 归属与完成状态

- 聊天端为每次用户提交生成独立任务 ID，并将 ID 附在拆分、执行、合并和串行回退的请求上。同样的文字、短时间连续提交、不同聊天设备均不作为合并依据。
- 子任务使用任务 ID 加子任务 ID 关联多次模型调用，显示实际执行的子任务输入，而非只显示简短标题。
- 聊天端回传任务状态和最终回答。模型调用返回、工具返回、子任务完成均不代表主任务完成。取消和已完成状态不会被迟到更新覆盖。
- 原有 infer.task 显示快照扩展到无子任务的普通任务。主任务允许从无子任务升级为确定的拆分计划，确定后子任务身份保持稳定。快照经汇聚设备转发给实际接收过请求的执行设备。
- 清理已完成任务时保留活动任务已返回的模型调用记录。本机推理中数量仍按本机实际模型请求计算，不计转发请求或工具等待。

## 展示

主列表保持单栏任务记录，展示原始请求、最终结果预览、任务耗时、执行设备和状态。拆分子任务也采用这个结构。详情默认显示任务输入与最终结果，继续使用“输出 / 输入 / 运行信息”。紧凑选择框可切换到具体模型调用，查看该次实际输入、原始输出、耗时和执行设备；运行信息附带最近的工具过程记录。

显示数据有传输和历史保留上限：主结果最多 4096 字符、子结果最多 2048 字符；有明确截断标记。原始用户输入尽量完整保留，超出快照字节预算时明确截断。工具过程保留最近记录；更完整的模型观察内容可从实际模型输入查看。快照预算为 56000 UTF-8 字节，为近场 64 KiB 消息及转发包装留出空间；不改变实际推理输入或最终聊天回答。

没有任务元数据的旧客户端无法可靠确定端到端边界，因此不再按相同文字和时间间隔猜测合并。完整新行为需要聊天端、算力端同时更新。

## 平板路由图

平板端 1.2.54 将入口与执行设备分开保存。上传动画只从聊天端到中间路由中心；收到明确执行设备后，单独播放一次路由中心到该设备的动画。入口设备不作为执行设备的默认值，设备1自行执行时也必须有明确分配。

| 请求状态 | 显示位置与文案 | 动画 |
| --- | --- | --- |
| 本地尚未发送 | 路由中心下方“等待发送” | 无 |
| 上传中 / 算力繁忙等待重新分派 | 路由中心下方“正在上传” / “等待分派” | 上传时仅第一段 |
| 已分配但仍排队 | 实际执行设备下方“等待执行” | 分配时仅第二段 |
| 已开始执行 | 实际执行设备下方“准备模型 / 加载模型 / 处理输入 / 生成中” | 执行阶段不重复播放分派动画 |

未报告细分阶段时显示“执行中”。每个请求使用独立、稳定的显示 ID；忙碌重试生成新传输 ID 时保留显示身份，重复阶段消息不重置阶段计时。结束、取消或改派会立即清除该请求的旧目标动画。

算力端 1.0.75 在已有改派逻辑确定新目标后发送 `infer.status`，携带 `state: rerouting`、`source: 旧执行设备`、`device: 新执行设备`、`text: 原因`。这是近场应用通道的显示扩展，不修改共享 inference-v2 包的调度契约；平板据此短暂显示改派提示。正常的入口到工作节点转发不发送改派通知。队列容量、选机策略、重试条件及超时预算保持不变。旧算力端仍能提供基本分配显示，具体改派原因需要升级算力端。

## 验证

覆盖同文独立请求、输入变化的多次模型调用、工具返回后继续执行、拆分与串行回退共享任务 ID、子任务独立输入和最终结果、多聊天设备身份隔离、执行设备最终快照转发、取消后的迟到数据以及快照大小限制。另执行双方 ArkTS 编译检查及桌面、窄屏 HTML 显示检查；未代替真机近场联测。

平板路由图增加 `routing-states.test.cjs`，覆盖本地等待、排队受理、图片直达设备3、设备1自行执行、阶段计时、忙碌重试、旧消息隔离、并发任务与改派旧路径清理。浏览器检查平板、宽屏、窄屏、多任务等待及减少动态效果设置，检查节点边界和卡片文本溢出。页面生成脚本须保留平板适配器，并可重复运行而不产生差异。
